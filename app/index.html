PHASE 0

ทำความเข้าใจระบบและกำหนดขอบเขต (Discovery & Scope)

2 Tasks
📌 TASK 0.1: ประชุมรับ Requirement และขอบเขตจากผู้ดูแลโครงการ
  • ระบุวัตถุประสงค์หลักของระบบ 3D (สำหรับมอนิเตอร์, สั่งการจริง หรือโชว์ผู้บริหาร)
  • ระบุกลุ่มผู้ใช้งานระบบ (พนักงานทั่วไป, ผู้ดูแลอาคาร, แขกภายนอก)
  • ระบุรายการสิ่งที่ต้องส่งมอบในระยะเวลาฝึกงาน (Deliverables)
  • กำหนดขอบเขตพื้นที่: เฉพาะห้อง A3 และ A4 หรือรวมทางเดินและพื้นที่แวดล้อม
  • กำหนดความสมจริงของโมเดล (เน้น Low-poly เรียบง่าย vs Realistic PBR)
  • ระบุอุปกรณ์ไฟฟ้าที่ผู้ใช้สามารถคลิกสั่งการได้ (Active Controls)
  • ระบุอุปกรณ์ที่ใช้แสดงสถานะอย่างเดียว ไม่ให้ผู้ใช้คลิกสั่งการ (Read-only Sensors)
ผลลัพธ์ที่ต้องได้: เอกสาร Project Scope, ขอบเขต In-Scope / Out-of-Scope และรายชื่อผู้รับผิดชอบ
📌 TASK 0.2: ศึกษาแพลตฟอร์ม 3D ที่พนักงานกำลังพัฒนาอยู่
  • สอบถาม Tech Stack แพลตฟอร์ม 3D (Three.js, React Three Fiber, Babylon.js หรือ Unity WebGL)
  • ตรวจสอบวิธีนำเข้าไฟล์โมเดล 3D และรูปแบบที่รองรับ (ปกติคือ .glb / .gltf)
  • ตรวจสอบระบบพิกัด แกนอ้างอิง (เช่น Y-Up vs Z-Up) และหน่วยวัด (Meters)
  • ตรวจสอบข้อจำกัดด้าน Performance (Polygon budget, Texture size, Draw calls)
  • ตรวจสอบวิธีคลิกเลือก Object (Raycasting, Naming, User Data tags)
  • ตรวจสอบวิธีเปลี่ยน Material/Emission เมื่อไฟเปิด หรือเปลี่ยนสีสถานะ
  • ตรวจสอบว่าแพลตฟอร์มมี Backend หรือ API Gateway อยู่แล้วหรือไม่
ผลลัพธ์ที่ต้องได้: Technical Spec แพลตฟอร์ม 3D และ Naming Convention ที่ตกลงร่วมกัน
PHASE 1

สำรวจพื้นที่จริงและรวบรวมข้อมูล (Space Survey & Asset Inventory)

3 Tasks
📌 TASK 1.1: สำรวจและเก็บข้อมูลห้อง A3 และ A4
  • ถ่ายภาพ Reference ห้อง A3, A4 ทุกมุม (มุมกว้าง, เพดาน, ผนัง, สวิตช์)
  • รวบรวมภาพ Top View หรือแบบร่างเดิมที่ทีมมีอยู่
  • วัดขนาดความกว้าง ยาว สูงจริงของห้อง A3 และ A4
  • วัดขนาดและตำแหน่ง ประตู, หน้าต่าง, เสา, โต๊ะทำงาน, ชั้นวางของ
  • กำหนดทิศทางห้องและจุด Origin (0,0,0) อ้างอิง
  • บันทึกตำแหน่งหลอดไฟ, แอร์, สวิตช์ และปลั๊กไฟทุกจุด
📌 TASK 1.2: จัดทำตารางรายการอุปกรณ์ 3D (Asset Inventory)
  • ทำบัญชีอุปกรณ์ไฟฟ้าห้อง A3 (ไฟเพดาน, แอร์, ปลั๊ก, เซนเซอร์)
  • ทำบัญชีอุปกรณ์ไฟฟ้าห้อง A4 (ไฟเพดาน, แอร์, ปลั๊ก, เซนเซอร์)
  • ระบุว่าอุปกรณ์ใดสามารถใช้โมเดลซ้ำกันได้ (Reusable Asset)
  • จัดลำดับความสำคัญของ Asset (Priority 1: อุปกรณ์ที่ต้องสั่งงานได้)
📌 TASK 1.3: สำรวจอุปกรณ์ในระบบ Home Assistant เดิม
  • ขอสิทธิ์เข้าใช้งานแดชบอร์ด Home Assistant ประจำ Innovative Village
  • จดบันทึกเวอร์ชัน Home Assistant และระบบเน็ตเวิร์กที่เชื่อมต่อ
  • ทำรายการ entity_id ของห้อง A3 ทั้งหมด (เช่น light.a3_main, switch.a3_fan)
  • ทำรายการ entity_id ของห้อง A4 ทั้งหมด
  • ตรวจสอบ Attributes ที่ส่งกลับมา เช่น brightness, temperature, state
  • ระบุอุปกรณ์ที่มีปัญหา ไม่เสถียร หรือขึ้น Unavailable
ข้อควรระวัง: ห้ามคัดลอก Access Token หรือ Password ลงใน Git หรือไฟล์ที่แชร์ภายนอกเด็ดขาด!
PHASE 2

กำหนดมาตรฐานโมเดล 3D ใน Blender (3D Asset Standards)

2 Tasks
📌 TASK 2.1: กำหนดมาตรฐานการปั้น (Modeling Guidelines)
  • ตั้งหน่วยวัดใน Blender เป็น Metric (1 Blender Unit = 1 เมตร) สเกล 1:1
  • กำหนดทิศทางแกน: +Y คือด้านหน้า, +Z คือขึ้นบน
  • กำหนดจุด Pivot / Origin: ฐานล่างสุดสำหรับของบนโต๊ะ / ด้านหลังสำหรับอุปกรณ์ติดผนัง
  • กำหนด Naming Convention ชัดเจน เช่น DEV_Light_A3_01, MAT_Light_Emission
  • กำหนด Polygon Budget: โครงห้อง < 5,000 Tris / อุปกรณ์ชิ้นละ < 500-1,500 Tris
  • กำหนดขนาด Texture ไม่เกิน 1024x1024 หรือ 2048x2048
  • ตั้งค่า Export เป็น glTF Binary (.glb) พร้อมเช็ก Apply Transforms (Ctrl+A)
📌 TASK 2.2: ปั้น Prototype Asset 1 ชิ้นเพื่อทดสอบ Pipeline
  • เลือกอุปกรณ์ที่ง่ายที่สุด 1 ตัว (เช่น โคมไฟเพดานห้อง A3)
  • ปั้นโมเดลตามขนาดจริง แยก Material ตัวโคมและหน้าหลอดไฟ (Emission)
  • Export เป็น .glb และนำเข้า glTF Validator ตรวจสอบความถูกต้อง
  • ส่งให้พี่นักพัฒนาลองโหลดเข้าแพลตฟอร์ม 3D เพื่อเช็ก Scale และการคลิก
  • นำ Feedback มาปรับปรุง Guidelines ก่อนปั้นอุปกรณ์ทั้งหมด
PHASE 3

ลงมือสร้างโมเดลห้องและอุปกรณ์ (Room & Device Modeling)

4 Tasks
📌 TASK 3.1 & 3.2: สร้างโมเดลโครงสร้างห้อง A3 และ A4
  • วางแบบแปลน Top View ใน Blender แล้ว Extrude สร้างพื้น ผนัง เพดาน ห้อง A3
  • เจาะช่องประตู หน้าต่าง เสาโครงสร้างห้อง A3 ให้ตรงตำแหน่งจริง
  • สร้างโมเดลโครงสร้างห้อง A4 ในลักษณะเดียวกัน
  • ใส่ Material พื้นฐาน (สีผนัง, พื้นไม้/กระเบื้อง, กระจกใส)
📌 TASK 3.3 & 3.4: ปั้นอุปกรณ์ไฟฟ้า และประกอบฉากรวม
  • ปั้นโมเดลหลอดไฟ / โคมไฟเพดาน ทุกรูปแบบที่มีใน A3, A4
  • ปั้นโมเดลเครื่องปรับอากาศ (Air Conditioner) ติดผนัง
  • ปั้นโมเดลสวิตช์ไฟติดผนังและปลั๊กไฟอัจฉริยะ
  • ปั้นโมเดลเฟอร์นิเจอร์หลัก (โต๊ะทำงาน, เก้าอี้) แบบ Low-poly
  • จัดวางอุปกรณ์ทุกชิ้นลงในห้อง A3, A4 ตามตำแหน่งจริง
  • ตรวจสอบ Hierarchy ใน Outliner และ Export ฉากสมบูรณ์เป็น .glb
PHASE 4

ศึกษาและทดสอบ Home Assistant API (IoT Communication)

3 Tasks
📌 TASK 4.1: ศึกษาและทดสอบ REST API
  • สร้าง Long-Lived Access Token ในหน้า Profile ของ Home Assistant
  • ทดสอบยิง GET /api/states เพื่อดึงสถานะอุปกรณ์ทั้งหมดผ่าน Postman หรือ cURL
  • ทดสอบยิง POST /api/services/light/toggle เพื่อสั่งเปิด/ปิดไฟทดสอบ
  • จดบันทึก Request & Response Schema สำหรับส่งต่อให้ทีมแพลตฟอร์ม
📌 TASK 4.2 & 4.3: ศึกษา WebSocket API และเลือกสถาปัตยกรรมเชื่อมต่อ
  • ทดสอบเชื่อมต่อ WebSocket ws://<ha-ip>:8123/api/websocket
  • ทดสอบ Authenticate ส่ง auth_ok ผ่านข้อความ JSON
  • ทดสอบส่งคำสั่ง subscribe_events เพื่อดักฟัง event state_changed
  • ลองเดินไปกดสวิตช์ไฟจริง แล้วดูว่ามี JSON Event วิ่งเข้ามาทันทีหรือไม่
  • ตัดสินใจเลือกวิธี: ยิงตรงผ่าน Frontend Browser หรือผ่าน Backend Gateway (แนะนำ Backend)
PHASE 5

ออกแบบระบบ Mapping ระหว่าง 3D และ IoT (Data Mapping)

2 Tasks
📌 TASK 5.1 & 5.2: กำหนด Mapping Schema และการแสดงผล Visual State
  • สร้างไฟล์ Mapping JSON ผูก 3D Object Name กับ entity_id
  • กำหนดการแสดงผลเมื่อ On: เปิดไฟ Emission สว่างจ้า / เปลี่ยน Material เป็นสีเหลืองอ่อน
  • กำหนดการแสดงผลเมื่อ Off: ปิด Emission กลับเป็นสีขาว/เทาปกติ
  • กำหนดการแสดงผลเมื่อ Unavailable: แสดงไอคอนสีแดงหรือไฮไลต์กระพริบเตือน
  • กำหนดพฤติกรรมกล้อง (Camera Focus) เมื่อผู้ใช้คลิกอุปกรณ์เพื่อดูรายละเอียด
PHASE 6

พัฒนา Prototype เชื่อมต่อระบบจริง (Integration Prototypes)

3 Tasks
📌 TASK 6.1: Read-only Prototype (แสดงสถานะแบบ Real-time ก่อน)

# คำถามที่ต้องนำไปถาม (Question) เหตุผลที่ต้องรู้ (Why it matters)
1 แพลตฟอร์ม 3D ใช้ Framework / Engine อะไรพัฒนา? ต้องรู้ว่าใช้ Three.js, React Three Fiber, Babylon หรือ Unity เพื่อเตรียมรูปแบบ Material ให้เข้ากัน
2 ต้องการไฟล์ 3D นามสกุลใด? มาตรฐานสากลคือ .glb แต่ต้องยืนยันว่าต้องการ .blend หรือ .gltf แยกโฟลเดอร์ไหม
3 มีงบประมาณ Polygon และขนาดไฟล์ต่อห้องหรือไม่? ป้องกันปัญหาโหลดช้าและเครื่องกระตุก โดยทั่วไปห้องหนึ่งไม่ควรเกิน 50,000 Tris และ < 15 MB
4 ระบบพิกัดและแกนในแพลตฟอร์มเป็นแบบใด? ป้องกันโมเดลกลับหัวหรือเอียงข้าง (Blender ใช้ Z-Up แต่ Three.js ใช้ Y-Up)
5 ห้อง A3 และ A4 มีแบบแปลนขนาดจริงหรือไม่? ถ้าไม่มี จะต้องเดินไปใช้ตลับเมตรวัดความกว้าง-ยาว-สูงจริงของห้องก่อนเริ่มปั้น
6 อุปกรณ์ใดต้อง "คลิกสั่งงานได้" และอุปกรณ์ใด "แสดงสถานะอย่างเดียว"? เพื่อจะได้แยก Mesh และเตรียม Material ให้ถูกต้อง (เช่น หลอดไฟต้องคลิกได้ แต่เซนเซอร์อุณหภูมิต้องโชว์เลข)
7 Home Assistant มี Environment สำหรับทดสอบ (Test Server) หรือไม่? ป้องกันการส่งคำสั่งผิดไปปิดแอร์หรือปิดไฟห้องที่กำลังมีผู้บริหารประชุมอยู่จริง
8 สามารถขอ Long-Lived Access Token สำหรับ Development ได้จากใคร? Token จำเป็นต่อการยิงทดสอบ API ผ่าน cURL / Postman
